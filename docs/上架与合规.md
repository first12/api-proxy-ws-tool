## 1. 单一用途声明（可直接粘贴）

### 中文（商店描述首段）

> **接口联调辅助工具。** 在联调阶段把指定接口的请求转发到本地或测试环境、为未就绪的接口返回本地 Mock 响应，并在 DevTools 中查看同一页面的 WebSocket 收发包、导出为 JSON。转发与 Mock 是写入侧，WebSocket 抓包导出是观测侧，都服务于“这条请求发到哪、通没通、返回了什么”这同一个调试动作，不提供任何其它功能。

### English（Chrome Web Store 的 Single Purpose 字段）

> **Single purpose: an API integration debugging helper.**
> The extension supports one debugging workflow: it forwards user-configured API requests to a local or test environment, returns local mock responses for endpoints that are not ready, and shows WebSocket traffic for the same inspected page inside DevTools with JSON export. Forwarding and mocking are the write side; WebSocket capture is the observation side. It does not modify page content, inject ads, track browsing, or provide unrelated features.

> 说明：两句话都强调“同一个调试动作的两侧”，避免被读成“代理 + 抓包”两个独立功能。描述里不出现“下载”“破解”“加速”“去广告”等无关词。

## 2. 最终权限形态

`manifest.json` 中的实际声明：

| 权限 | 类型 | 用途 | 安装期是否提示 |
|---|---|---|---|
| `storage` | 必选 | 保存本地规则与同步状态 | 否 |
| `declarativeNetRequestWithHostAccess` | 必选 | 使用 DNR 做请求重定向与请求头修改；所有动作都要求已授予对应主机权限 | 否 |
| `scripting` | 必选 | 动态注册 Mock 拦截脚本（仅限用户已授权主机；无启用 Mock 规则时注销） | 否 |
| `optional_host_permissions: ["*://*/*"]` | **可选** | 声明可选范围；实际只按用户规则里的域名逐个申请 | 否 |

明确**不申请**：`host_permissions`（尤其不含 `<all_urls>`）、`tabs`、`webRequest`、`webRequestBlocking`、`debugger`、`proxy`、`cookies`、`clipboardRead`。

**为什么用 `declarativeNetRequestWithHostAccess` 而不是 `declarativeNetRequest`**

- 后者允许在无主机权限时执行 block/allow，权限面更大；
- 本项目只做 redirect 与请求头修改，且所有规则都必须落在用户已授权的域名上，`WithHostAccess` 更贴合最小权限原则，也不会在安装时产生额外警告。

**为什么声明 `web_accessible_resources`（仅 3 个包内脚本）**

- 为了彻底去掉“抓源码字符串再 `eval`”的远程代码嫌疑，钩子改为**静态脚本注入**：`ws-hook-source.js` 是打包内自执行文件，通过 `web_accessible_resources` 暴露给页面，面板只用 `inspectedWindow.eval` 创建一个 `<script src="chrome-extension://…/ws-hook-source.js">` 标签，`eval` 里不再出现任何源码字符串；
- 暴露面收敛到三个包内文件：WS 脚本只包装 `WebSocket` 并把帧写入 `window.__WS_FRAMES__` / `window.__WS_CONNECTIONS__`；Mock 相关文件只做匹配与 fetch/XHR 拦截。均不读取页面其它数据、不发网络请求、不接收远程指令；
- 选取理由与风险：DevTools 面板注入不依赖主机权限，任何页面都能采集 WS，因此 WS 钩子继续走 WAR；Mock 需要日常页面生效，才单独申请 `scripting`。页面严格 CSP（`script-src` 未放行 `chrome-extension:`）下 `<script>` 可能被拦截，属于浏览器实测项，见第 11 节。

## 3. 权限逐条 justification（英文可粘贴）

### 3.1 `storage`

> Used to store the user's own redirect rules and the last sync status on the local device. No browsing data, request content, or WebSocket payload is stored or transmitted.

- 用户可感知：关闭浏览器再打开，规则仍在；同步失败时 popup 能看到提示。
- 不申请会怎样：规则无法持久化，扩展无法使用。

### 3.2 `activeTab`（已移除）

> v0.7 已从 manifest 删除。上一版声明它是为了把“当前调试页 origin”并入授权请求，但代码从未调用 `chrome.tabs.query`，属于声明未使用权限；为遵守最小权限原则直接移除。现有授权入口由用户在配置页/弹窗中点击规则域名触发，不依赖当前标签页 URL。

### 3.3 `declarativeNetRequestWithHostAccess`

> Used to apply redirect rules and request-header changes that the user creates explicitly. Rules only take effect on domains the user has granted at runtime, and the extension never reads request or response bodies.

- 用户可感知：保存并授权后，请求命中规则时被改写到测试地址，并按规则设置/删除请求头（如测试环境的 token）。
- 不申请会怎样：无法改写请求目标、无法修改请求头，联调能力完全不可用（这是本扩展的核心能力之一）。

### 3.4 `scripting`（Mock 拦截脚本注册）

> Used only to register the bundled Mock interceptor (`rules-model.js` + `mock-inject.js` in the MAIN world, plus a small isolated-world bridge) on origins the user has already granted. Content scripts are registered dynamically at runtime, are limited to those granted origins, and are unregistered as soon as no enabled Mock rule remains.

- 用户可感知：开启 Mock 规则并授权域名后，页面脚本的 fetch/XHR 命中规则时返回伪造响应；关闭最后一条 Mock 规则后脚本被注销，页面恢复原生 fetch/XHR。
- 不申请会怎样：Mock 只能在打开 DevTools 面板时通过注入降级生效，日常浏览页面无法使用 Mock。
- 最小化说明：不注册任何静态内容脚本、不使用 `<all_urls>` 匹配、不注入未授权站点；`scripting` 本身不产生“读取所有网站数据”的安装提示。

### 3.5 可选主机权限 `*://*/*`

> Optional and never granted at install. The extension declares a broad optional range only so it can request the exact origins the user typed (for example `https://192.168.1.100/*`). v0.7 removed `activeTab`, so no current-page origin is added. Each request is triggered by an explicit user click, shows the concrete origins in the browser prompt, and can be revoked at any time from the extension details page.

- 用户可感知：每新增一个不同域名，第一次启用时点【授权此域名】，系统弹窗只列出该域名。
- 不申请会怎样：规则可以保存但不生效，列表显示“待授权”。

**审核要点**：`optional_host_permissions` 不会显示为“读取所有网站数据”；实际请求的是具体 origin。填写理由时务必强调“按用户输入的域名逐个申请、用户手势触发、可随时撤销”，不要写成“需要访问所有网站”。

### 3.6 未申请的权限（写明“不需要”也是加分项）

> The extension does not request `debugger`, `proxy`, `webRequest`, `webRequestBlocking`, `tabs`, or `cookies`. WebSocket frames are observed from the inspected page's own memory through the DevTools API; no network interception or certificate handling is involved.

## 4. 授权交互流程（用户视角）

```
添加/编辑规则（host = 192.168.1.100）
        │
        ▼
列表显示：权限：待授权  [授权此域名]
        │  点击（用户手势）
        ▼
收集 origins = ["https://192.168.1.100/*", "http://192.168.1.100/*"]
        │
        ▼
chrome.permissions.request({ origins })
        │
        ├── 同意 → permissions.onAdded → sw.js 重新同步
        │        → 只编译已授权 scheme 的 DNR 规则
        │        → 列表：权限：已授权
        │
        └── 拒绝 → request 返回 false
                 → 提示“仍不会生效，可再次点击重试”
                 → 按钮保留，不置灰、不锁定
```

关键点：

- `chrome.permissions.request` 必须在用户手势中调用；点击按钮即满足。
- 拒绝后**不写入任何“已拒绝”状态**，也不禁用按钮，用户可反复重试（[重试]不会卡死）。
- 授权成功后由 `chrome.permissions.onAdded` 触发同步，不依赖 popup 保持打开。
- 撤销授权（扩展详情页 → 网站访问权限）由 `chrome.permissions.onRemoved` 触发同步，对应规则自动退出 DNR。

## 5. 权限降级表现（未授权 / 撤销 / 重启）

| 场景 | 规则数据 | DNR 规则 | UI 表现 | 恢复方式 |
|---|---|---|---|---|
| 新增规则但未授权 | 已保存（`storage.local`） | **不写入** | 行内“权限：待授权”+【授权此域名】 | 点击授权；`onAdded` 自动同步 |
| 授权被拒绝 | 已保存 | 不写入 | 同上 + 错误条“未获得授权…” | 再次点击按钮重试 |
| 只授权了 https | 已保存 | 仅生成 https 规则 | “权限：已授权（部分）” | 再点一次补充 http |
| 用户撤销部分域名 | 保留 | 该域名规则在下次同步时移除 | 对应行回到“待授权” | 重新授权 |
| 浏览器重启 | 保留 | 保留（可选授权随配置文件持久化） | 与重启前一致 | — |
| 同步失败（规则非法等） | 保留 | 逐条降级，失败项被隔离 | 黄色状态条显示 `lastSyncError` +【重试同步】 | 修复规则或点重试 |
| 扩展刚安装、无任何规则 | 空 | 空 | 列表空态 | 新增规则 |

**重要语义**：规则“存在但不生效”是明确设计，不是故障。popup 必须同时展示“已保存”和“未授权”两个事实，避免用户误以为已经生效。

## 6. DNR 同步的过滤与失败处理

`sw.js` 的同步顺序：

1. 读取 `proxyRules`；
2. 对每条启用规则，归一化 host（去协议/端口/路径），按 `https` / `http` 分别调用 `chrome.permissions.contains({origins:[scheme://host/*]})`；
3. **只把已授权 scheme 编译成 DNR 规则**，未授权规则计入 `skippedNoPermission`，不提交给浏览器；
4. 读取现有动态规则，一次性 `updateDynamicRules({removeRuleIds, addRules})`；
5. 若整批失败（例如某条 urlFilter 非法），先清空，再**逐条 `addRules`**，失败的条目单独记入 `failed`，其余规则照常生效；
6. 结果写入 `storage.local` 的 `proxySyncStatus`：

```json
{
  "at": 1762329600000,
  "ok": true,
  "configured": 5,
  "applied": 7,
  "skippedNoPermission": 1,
  "skippedOther": 0,
  "exceeded": false,
  "failed": [],
  "lastSyncError": null
}
```

- `lastSyncError` 为字符串时，popup 顶部黄色条展示并给出【重试同步】（向 SW 发 `{type:"resync"}`）。
- 同步串行化（内部 Promise 链），避免两次 storage 变更交错覆盖。
- `permissions.onAdded` / `onRemoved`、`onInstalled`、`onStartup`、`storage.onChanged` 都会触发同步。

## 7. 数据处理与隐私声明

### 7.1 声明正文（中文，可直接放隐私政策页）

1. **不收集任何个人数据。** 本扩展不收集、不上传、不共享、不出售浏览历史、请求内容、响应内容或 WebSocket 报文。
2. **代理规则只存在本机。** 规则保存在 `chrome.storage.local`，不上传、不云同步；卸载扩展即删除。规则中的请求头（可能含访问令牌）同样只存本机明文、不上传；导出规则时默认脱敏。
3. **WebSocket 帧只存在页面内存。** 帧数据由注入到被检查页面的脚本保存在该页面的内存中，刷新/关闭页面即释放；只有用户点击“导出”时才会生成本地文件，文件去向由用户自行决定。
4. **权限按需申请。** 安装时不申请任何网站访问权限；只有在用户新增规则并点击【授权此域名】后，才会针对该域名弹出系统授权框；授权可随时撤销。
5. **无分析 SDK、无远程配置。** 扩展不包含统计、埋点、崩溃上报、A/B 或远程开关；所有代码随安装包分发，运行时不下载、不执行任何远程代码。
6. **不读取无关数据。** v0.7 已移除 `activeTab`：授权范围只来自用户创建的规则域名，不读取当前标签页 URL、不写入存储、不打印日志、不外发。
7. **联系方式**：仓库 Issue（`gitee.com/first12/api-proxy-ws-tool`）。
8. **变更**：隐私政策更新会在商店描述与仓库同时标注日期。

### 7.2 English privacy summary（商店后台“数据使用”填写参考）

> This extension collects no user data. Redirect rules and user-configured request headers are stored locally via `chrome.storage.local` and are never uploaded; exported rule files redact sensitive header values by default. WebSocket frames are kept in the inspected page's memory and are only written to a local file when the user explicitly exports them. No analytics, telemetry, remote configuration, or remotely hosted code is used. Host permissions are optional and requested per domain only after an explicit user action; they can be revoked at any time in the browser's extension settings.

### 7.3 商店后台勾选

- 是否收集用户数据：**否**。
- 是否使用远程代码：**否**（全部脚本随包分发；DevTools 注入的是打包内同一份代码）。
- 是否包含广告/跟踪：**否**。
- 是否面向儿童：**否**。
- 隐私政策 URL：`https://first12.github.io/api-proxy-ws-tool/privacy.html`（仓库根目录 `privacy.html`，通过 GitHub Pages 部署）

## 8. 无远程代码说明（应对审核问询）

| 审核可能问 | 回答 |
|---|---|
| 为什么用 `eval`？ | 只使用 `chrome.devtools.inspectedWindow.eval`，且内容仅为一小段固定桥接代码：创建 `<script src="chrome-extension://…/ws-hook-source.js">` 并检查版本号，不含任何源码字符串或外部输入。 |
| 执行的是什么代码？ | 执行的是扩展包内 `ws-hook-source.js`（自执行文件），通过 `web_accessible_resources` 静态加载，不来自网络、不来自用户输入、不拼接外部字符串。 |
| 有没有 `fetch` 远程脚本？ | 没有。原实现 `fetch("ws-hook-source.js")` + `eval` 已删除。 |
| 有没有 `web_accessible_resources`？ | 有，且只暴露 `ws-hook-source.js`、`rules-model.js`、`mock-inject.js` 三个包内文件；WS 脚本只做帧采集，Mock 脚本只做 fetch/XHR 拦截，均不访问其它页面数据、不发网络请求、不接收远程指令。 |

如果审核仍要求“零动态执行”，DevTools 钩子可退回 `inspectedWindow.eval` 桥接（当前即此方案）；Mock 的 `scripting` 注册无法用 DevTools 替代成日常能力，只能保留面板内降级。

```
[What the extension does]
This extension is a frontend debugging helper with two capabilities used in the same workflow:
(1) redirect page HTTP requests by host + path to a test environment, and
```

```text
API Proxy & WS Capture Tool is a debugging helper for frontend, QA and backend engineers who work against staging, test or local environments.

It covers three jobs in one place.

FORWARD REQUESTS
Point specific API calls to a local server, a test cluster or any other address, matched by host and path. Use path replacement to keep the original query string, or a full target URL for complete control.

MOCK UNFINISHED ENDPOINTS
Return a custom status code, response headers and JSON body for endpoints that are not ready yet, with an optional delay. Works with page fetch and XMLHttpRequest calls.

CAPTURE AND EXPORT WEBSOCKET TRAFFIC
Open DevTools and switch to the wsData panel to see every WebSocket connection on the page: open and close events, incoming and outgoing frames, grouped per connection. Export everything as structured JSON for logs, bug reports or further analysis.

BUILT AROUND EXPLICIT PERMISSION
Rules only apply to domains you explicitly authorize. Nothing is read or modified on other sites, and permissions can be revoked at any time from the extension details page.

PRIVACY FIRST
No account, no analytics, no servers. Rules are stored locally in chrome.storage.local. Captured WebSocket data lives only in the inspected page's memory and in files you export yourself. All code ships inside the package; nothing is downloaded or executed remotely at runtime.

GOOD TO KNOW
- Request headers can only be modified by a dedicated "Headers Only" rule. Header rules do not apply to redirected requests, so they cannot be combined with request forwarding.
- Mock rules only cover requests issued by page JavaScript (fetch or XHR), not document navigation or resource requests.
- WebSocket capture is read-only. It cannot modify or forward messages.
- Connections opened before the DevTools panel loads cannot be captured; reload the page to reconnect.
```
