# api-proxy-ws-tool · 界面设计说明

## 1. 设计取向

一句话：**桌面工具式的高密度信息界面，中性灰白为底、单一青蓝强调色，用表格和左右分栏承载真实字段；靠排版、对齐和 1px 分隔线建立秩序，不靠卡片、渐变和图标装饰。**

三条落地原则：

1. **信息先于装饰。** 页面 1 的 17 条规则在一屏内可比较；页面 2 的连接与帧同时可见，不靠折叠展开换取空间。
2. **状态用文字，不只靠颜色。** 每个状态点旁边都有文字标签（生效 / 已停用 / 配置错误 / Mock 不生效 / 连接中 / code 1000），色点只是辅助。
3. **一个强调色。** 只有青蓝 `#2B6A8C` 承担选中、主按钮、聚焦环和 in 方向；绿 / 黄 / 红仅用于语义状态，不参与装饰。

只做浅色主题。原因：面板嵌在 DevTools 里，桌面开发工具的默认语境是浅色；一套主题可以把色阶、对比和截图验证做扎实，而不是用两套半成品。

## 2. 与代码的语义对齐

先读 `popup.html / popup.js / devtools-panel.html / devtools-panel.js`，并核对了 `sw.js / ws-hook-source.js`。原型里没有新增数据字段，展示值均由现有字段派生。

### 2.1 真实字段

| 对象 | 字段 | 来源 |
| --- | --- | --- |
| 规则 | `host`、`pathPattern`、`type`（proxy / mock）、`proxyMode`（pathReplace / fullUrl）、`proxyPathPrefix`、`proxyTarget`、`mockBody`、`enable`、`id` | `popup.js` 的 `collectForm()` / `validate()` |
| 连接 | `id`（ws-N）、`url`、`openedAt`、`closedAt`、`closeCode`、`frameCount`、`truncated` | `ws-hook-source.js` |
| 帧 | `direction`（open / close / in / out）、`timestamp`（内部 `ts`）、`payload` | `ws-hook-source.js`，导出时字段名为 `timestamp` |

### 2.2 代码约束如何进入界面

- **没有 method 字段。** 限制条件在 DNR 的 `condition.resourceTypes`，实际是全 5 类：`main_frame / sub_frame / xmlhttprequest / other / websocket`。所以工具栏右侧写“资源类型 全部 5 类”，规则行不出现“方法”列。
- **priority 固定为 1。** `sw.js` 写死 `priority: 1`，界面显示 `P1`，不做可编辑下拉。每条启用规则会生成 https / http 两条 DNR 规则，页脚写“已启用 9 条 → 生成 18 条 DNR 规则”，与 `dnrCount() * 2` 一致。
- **Mock 不生效。** `sw.js` 明确 DNR 无法返回自定义响应体，`type=mock` 不编译。界面给 Mock 行加“DNR 不支持”副标签和“Mock 不生效”状态，不伪装成可用。Mock 的“重定向目标”列显示 `mockBody` 的规模，不是新字段。
- **匹配地址由 `host + pathPattern` 拼接。** 表格把 host 用淡色 mono、path 用深色 mono 并排，强调它们共同构成一个 urlFilter。
- **重定向目标是派生展示。** `pathReplace` 显示 `proxyPathPrefix`，`fullUrl` 显示 `proxyTarget`。抽屉里仍按代码分成两种模式，字段名一致。
- **帧缓冲上限 2000。** 帧表底部写“缓冲上限 2000 帧”，`truncated` 显示为“截断 / 已截断”。
- **payload 上限 8000 字符，二进制为 `[binary]`。** 大 payload 查看器标题右侧写“901 字符 · 上限 8000 字符”，与 `slice(0, MAX_PAYLOAD)` 一致；长度列是 `payload.length` 的字符数，不是字节数。
- **连接状态由 `closedAt` 派生。** 有 `closedAt` 显示灰色点 + `code N`，否则绿色点 + “连接中”。
- **同名 host+path 的重复规则会被 `validate()` 拒绝。** 因此原型里 17 条规则的 `host + pathPattern` 均不重复；冲突提示只来自通配重叠（r2 的 `*` 覆盖 r1、r11），不伪造“完全重复”。
- **“配置错误”规则可以存在。** 保存时会被校验拦截，但历史 storage 数据或未来导入可能带入不完整规则。界面选择“显示并标红”，而不是静默隐藏。该行保存按钮禁用，字段下方给出具体原因。

### 2.3 现状与新增（避免把设计当成已实现）

| 能力 | 代码现状 | 原型 |
| --- | --- | --- |
| 规则列表 / 行内开关 / 编辑 / 删除 | 已有（popup） | 保留语义，改为表格 |
| 域名权限状态（已授权 / 待授权 / 部分） | 已有（popup 逐条 `contains`） | 状态列可派生；本次截图样本假定域名均已授权，因此未出现“待授权” |
| 搜索 / 状态筛选 / 批量 / 空态 | 无 | 新增设计 |
| 导入 / 导出 | 无 | 新增设计（按钮只表达入口，不伪造进度） |
| 连接、帧、清空、导出 JSON | 已有（DevTools 面板） | 保留字段与导出语义 |
| 连接搜索 / host 过滤 / 状态筛选 / 只看有帧 / 已加载计数 | 无 | 新增设计 |
| 帧方向筛选 / payload 搜索 / 暂停滚动 / 大 payload 查看器 | 无（现面板每个新帧都强制滚到底） | 新增设计 |
| 命中计数 / “未命中” | **没有任何命中统计** | 不做。状态列只表达配置与授权层面的事实 |

**关于“未命中”：** 代码没有请求命中计数器，画一个“未命中”状态只能靠编。界面改用“生效 / 已停用 / 配置错误 / Mock 不生效”，把可验证的事实说清楚；将来若接入计数，同一状态列可以承载“未命中”，不需要改布局。

**关于“冲突”：** 它是从重叠 urlFilter 派生的提示，不是现有字段。`sw.js` 的 priority 恒为 1，多条规则重叠时命中顺序不确定，所以提示文案只写“同优先级下 DNR 命中顺序不确定”，不承诺谁先命中。

| 令牌 | Hex | 用途 |

| `--bad` / `--bad-bg` / `--bad-line` | `#A13E36` / `#F8EAE8` / `#E7C8C4` | 配置错误、删除悬停 |

### 3.2 为什么是这套

- **主色选青蓝而不是“互联网蓝”。** `#2B6A8C` 的饱和度低、明度中等，像 IDE 的选择色和链接色，不像 SaaS 营销页的高饱和 `#2563EB`。它和灰白底之间对比约 5.9:1，白字放在上面也可读。
- **灰阶偏冷。** `#F4F5F6 / #FAFBFC / #E4E7E9` 都带一点蓝绿倾向，与主色同温，避免暖灰带来的“纸张/米色”感。
- **状态色全部压暗。** 绿 `#2E7A57`、黄 `#8A6114`、红 `#A13E36` 都在中低明度，只在 6px 点和 10.5px 文字上出现，不发光、不铺满行。
- **对比度取舍。** `--muted` 对白底约 5.1:1，可用于正文辅助信息；`--faint` 约 2.8:1，只用于时间、host、说明等非关键元数据，不承载操作或错误信息。如果后续要做 WCAG AA 审计，优先把 `--faint` 调到 `#7A8289`，而不是整体换色。

## 4. 字号、间距与尺寸

### 4.1 字号阶梯

| 字号 | 字重 | 用途 |
| --- | --- | --- |
| 15px | 600 | 页面标题（接口代理 / WS 抓包） |
| 13px | 600 | 抽屉标题、空态标题 |
| 12px | 400–600 | 表格正文、规则行、连接 id、主按钮 |
| 11.5px | 400–500 | 控件文字、状态标签、字段标签、帧 payload |
| 11px | 400 | 规则行主路径、连接 url、副标题 |
| 10.5px | 400–500 | 表头、时间、长度、页脚、徽标、说明 |
| 10px | 400 | 连接列表第二行、mono 元数据 |

字体栈只用系统字体，无外部 CDN：

```css
--sans: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
        "Microsoft YaHei", "Source Han Sans SC", "Noto Sans CJK SC", sans-serif;
--mono: ui-monospace, "SF Mono", "Cascadia Mono", "Consolas",
        "Roboto Mono", "Liberation Mono", monospace;
```

**为什么这么小：** 这是嵌入浏览器的工具面板，不是阅读型网页。12px 作为正文、10.5px 作为元数据，能在 900px 高度里放下 17 条规则，在 800px 高度里放下约 21 行帧。字号阶梯取 1–1.5px 的细步进，避免出现 14/16 这种“网页正文”尺寸把工具界面撑松。

### 4.2 间距尺度

以 4px 为基数：`4 / 6 / 8 / 10 / 12 / 14 / 16 / 18 / 20 / 24`。

| 位置 | 数值 |
| --- | --- |
| 页面左右留白 | 20px |
| 表格单元格 | 左右 12px，首列左 20px，末列右 20px |
| 抽屉内边距 | 18px 20px 20px |
| 连接列表项 | 7px 12px 8px 14px |
| 工具栏 / 帧工具条 | 左右 16px |

### 4.3 关键高度

| 元素 | 高度 |
| --- | --- |
| 应用顶栏 | 52px |
| 规则工具栏 | 46px |
| 批量操作条 | 40px |
| 规则表头 / 规则行 | 30px / 42px |

## 5. 圆角、边框、阴影

### 5.1 圆角

- `3px`：chip、类型标签、复选框、状态徽标、计数徽标。
- `4px`：按钮、输入框、选择器、分段控件。
- 不使用 8px 以上的卡片圆角；抽屉、表格、面板一律直角或仅 4px。
- 6px 的点、9px 的胶囊只用于开关轨道和状态点，属于控件形状，不是“卡片圆角”。

### 5.2 边框

- 统一 `1px solid`。
- 结构分隔用 `--line #E4E7E9`；控件描边和左右分栏用更明确的 `--line-2 #D3D8DB`。
- 表格行分隔更淡：规则行 `#EFF1F3`，帧行 `#F2F4F5`，避免 17 行横线形成栅格噪声。
- 选中态不靠加粗边框，靠 `--accent-bg` 底 + 连接项左侧 2px 竖条。

### 5.3 阴影

全页只有两处阴影，且都是“层浮起”的信号，不用于卡片：

```css
/* 右侧编辑抽屉 */
box-shadow: -16px 0 32px rgba(22,25,28,.07);
/* 底部 payload 查看器 */
box-shadow: 0 -12px 24px rgba(22,25,28,.06);
```

**为什么几乎不用阴影：** 工具界面的层级应该由底色（`#FFFFFF / #FAFBFC / #F0F2F3`）和 1px 线表达。大量卡片阴影会让界面变成营销页，也会在 DevTools 的浅灰底上显得脏。

## 6. 组件规则

- **按钮层级：** 主按钮只有“新建规则”“导出 JSON”；描边按钮用于“导入 / 导出 / 清空”；行内“编辑 / 删除”是无底文字的 text button，删除只在悬停变红。
- **开关：** 只表达启用/停用，开启用主色，关闭用 `--line-2`。不用绿色表示“开”，避免和“生效”状态色混淆。
- **筛选 chip：** active 用 `--accent-bg` 底 + `--accent-line` 边 + `--accent-hover` 字；计数用 mono 10.5px、`--faint`，active 时变主色。
- **状态：** 6px 圆点 + 文字。点色只承担辅助，文字始终存在。
- **表格：** `table-layout: fixed` + sticky 表头 + 单行省略。列宽写死，保证 17 行纵向对齐一致；host 用 `--faint`，path 用 `--ink`，形成“域名弱、路径强”的阅读顺序。
- **抽屉：** 从顶栏下方滑出，宽 392px，覆盖表格右侧。字段分“匹配 / 动作”两组；错误信息贴在字段下方，用 3px 红色竖条 + 10.5px 文案；底部说明会随模式变化（生成 2 条 DNR / 不生成 / 缺目标）。
- **空态：** 表格区域内绝对定位覆盖，不画插画。标题 + 一句解释 + 两个动作（清除筛选 / 新建规则）。无规则和搜不到结果使用不同文案。
- **大 payload 查看器：** 底部浮层，从连接列右侧开始，高 252px；头部有“帧 · 时间 · 方向”、字符数与 8000 上限、复制/关闭；正文 mono 11.5px / 1.65，`pre-wrap` + `break-all`。
- **焦点环：** 所有可聚焦控件使用 `0 0 0 3px var(--ring)`，不保留浏览器默认 outline。

## 7. 页面 1：代理配置

### 7.1 信息架构（自上而下）

1. **顶栏 52px**：品牌方块 AP、标题“接口代理”、规则统计（17 条 / 9 生效 / 4 停用 / 4 异常 / 2 组冲突）、导入、导出、新建规则。
2. **工具栏 46px**：搜索框（host / 路径 / 目标）、状态 chips（全部 / 生效 / 已停用 / 异常）、右侧“资源类型 全部 5 类”。
3. **批量条 40px**：仅在有选中且列表非空时出现。显示“已选 N 条规则”、启用 / 停用 / 删除 / 取消选择。
4. **规则表**：8 列，横向优先级从“识别”到“判断”再到“操作”。
5. **状态条 26px**：左侧“同步为 declarativeNetRequest 动态规则 + 已启用 9 条 → 生成 18 条 DNR 规则”，右侧“上次同步 12:04:52”。
6. **编辑抽屉**：点“新建规则”或行内“编辑”从右侧进入。

### 7.2 列的定义

| 列 | 宽度 | 内容 | 理由 |
| --- | --- | --- | --- |
| 选择 | 54px | 自绘复选框 | 支持批量；54px 是为了给 20px 左内边距 + 14px 控件留出余量，避免省略号 |
| 启用 | 64px | 行内开关 | 最高频操作，放最左，点一下即写入 storage 并触发 resync |
| 匹配地址 | 352px | host（淡 mono）+ path（深 mono） | 一条规则的核心身份 |
| 类型 | 150px | 转发/Mock 标签 + 路径替换/完整 URL 副标签 | 同时回答“做什么”和“怎么做” |
| 重定向目标 | 弹性 | 前缀 / 完整 URL / Mock 规模 / 未设置 | 只显示当前模式真正生效的那个字段 |
| 状态 | 140px | 生效 / 已停用 / 配置错误 / Mock 不生效 | 派生自 enable、type、target |
| 优先级 | 100px | `P1` + 冲突徽标 | 代码固定为 1；冲突是提示，不可编辑 |
| 操作 | 96px | 编辑 / 删除 | 右对齐，符合表格操作惯例 |

### 7.3 关键状态

- **列表行：** 42px，悬停 `#FAFBFC`；选中行 `#F2F7F9`；未选中不显示左侧竖条，避免 17 行都出现彩条。
- **行内开关：** 30×17，开启主色。关闭行状态文字同时变为“已停用”，开关和状态互相解释。
- **编辑态：** 抽屉打开 r7（`/da-digital/api/session/detail`，缺 `proxyPathPrefix`）。目标字段显示红框、字段标签变红、下方“必填。为空时该规则不会生成 DNR 规则，等同于失效”，底部保存禁用。r7 在列表里也保持“配置错误”，形成列表与抽屉的闭环。
- **空态：** 搜索 `zzz` 时显示“没有匹配的规则”，解释包含关键词的 `span.q`，动作为“清除搜索 / 新建规则”；规则总数为 0 时标题改为“还没有代理规则”，解释改成 DNR 同步说明。
- **批量选择态：** 选中 3 行后，表头复选框呈半选（`.mixed`，7px 横线），批量条出现，行底色变浅青，批量条内“已选 3 条规则”用 mono 数字。
- **空列表保护：** 搜索无结果时批量条隐藏，避免出现“0 行但已选 3 条”的矛盾状态。

### 7.4 交互决策

- 用**表格而不是卡片**：规则是同一结构的记录，17 条需要纵向比较；卡片会把标签重复 17 遍，且无法对齐 host/path。
- 用**抽屉而不是整页表单**：编辑时仍能看到列表上下文，且与 popup 的即时保存语义一致。
- 用**行内开关**：代码中开关会立即持久化并 resync，放在行内比进抽屉更符合使用频率。
- 用**派生状态**而不是假的“命中率”：没有计数器就不画。状态列同时是筛选入口（chips 与状态列使用同一套 key）。
- 用**文本 + 淡底**表达冲突：不引入第二种强调色，不把整行染黄。
- 导入 / 导出**只给入口和格式语义**（`proxyRules` 数组），不画假的进度条或文件选择器。

## 8. 页面 2：WS 抓包

### 8.1 分栏方式与理由

采用**左右分栏**：左侧 336px 固定连接索引，右侧自适应帧表格。理由：

1. **帧是宽表。** 时间、方向、长度、payload 摘要、查看入口——上下堆叠会把可用宽度压到连接列表的宽度，payload 摘要几乎不可读；左右分栏把宽屏的宽度留给帧表。
2. **DevTools 面板是“宽而矮”。** 1200×800 下垂直空间只有约 700px，上下分栏只能给帧表 300px 左右；左右分栏能给到约 20 行。
3. **连接是索引，不是内容。** 用户先按 host/url 找到连接，再读帧。连接列表不需要展开就能看到帧数和状态，避免了原生 `<details>` 那种“40 多个折叠项、每次都要点开”的问题。
4. **切换连接不跳滚动位置。** 左侧选中一条，右侧整体替换；不会像手风琴那样把下方所有连接推走。

### 8.2 左侧连接索引

- **面板头 36px：** “连接” + 总数徽标 + “只看有帧”开关。徽标显示**全部连接数**，不受筛选影响，保证“现在到底抓了多少条”始终可见。
- **过滤区：** 搜索框（url 或连接 id）+ host 下拉（`全部 host` / 具体 host）。
- **状态 chips：** 全部 / 连接中 / 已关闭。
- **连接项：** 两行。第一行状态点 + `ws-N` + 去协议的 url；第二行打开时间、`N 帧`、截断标记、右侧 `code N` 或“进行中”。没有展开箭头。
- **底部 26px：** `已加载 22 / 28 条` + “滚动加载更多”。这里的 28 是**筛选后**的数量，22 是当前已渲染数量；与头部徽标的 48（总数）分开，避免把“总数”和“筛选结果”混成一个数字。
- **滚动：** 列表自身滚动，滚动到底追加，不一次性铺 48 条；这正是“连接多时”的解法之一。

### 8.3 右侧帧区

- **连接头：** 状态点 + `ws-N` + 完整 url；第二行 `打开 12:01:23.629 · 关闭 12:02:25.547 · closeCode 1000 · 28 帧 · 未截断`。连接中则显示“连接中”，不显示关闭时间和 code。
- **方向 chips：** 全部 / in / out / open / close，每个带计数（由当前连接的帧数组实时计算）。in 用主色底，out 用中性底，open/close 降为淡色文字，符合“业务数据 vs 生命周期事件”的权重。
- **payload 搜索：** 只过滤 payload 文本，不参与连接筛选，避免两个搜索框语义混淆。
- **暂停滚动：** 当前实现每来一帧就 `scrollTop = scrollHeight`。原型把它变成显式状态：开关开启后底部显示“已暂停滚动”，关闭时显示“跟随最新”。暂停时不打断用户查看历史帧。
- **帧表：** 时间（mono，含毫秒）、方向徽标（in 主色底 / out 中性底 / open·close 淡色）、长度（字符数，>600 加粗）、payload 摘要（单行省略）、查看（仅大 payload 出现）。
- **帧脚：** `显示 24 / 24 帧 · 缓冲上限 2000 帧`；截断连接追加“该连接已被截断”。
- **大 payload：** 摘要超过 600 字符或标记为 big 时出现“查看”；点击后底部浮层显示完整 payload、字符数、8000 上限、复制/关闭。
- **空态：** 未选连接显示“左侧选择一个连接”；连接 0 帧显示“该连接没有帧（可能在建连阶段就关闭）”；筛选无结果显示“当前筛选条件下没有帧”。

### 8.4 “连接很多”的场景怎么解

`ws-panel-many.png` 用 48 条连接、host 固定为 `10.114.0.11`、开启“只看有帧”：

- 头部徽标 48（总量），筛选后 28，已加载 22，底部明确“滚动加载更多”。
- 列表是**扁平可滚动的索引**，不是 48 个需要逐个点开的折叠块；搜索、host、状态、只看有帧四个条件叠加后，目标连接通常在 1–2 屏内。
- 选中 `ws-31` 后，右侧直接显示它的 28 帧；列表滚动位置保持（`scrollTop = 176`），选中的连接不会被滚走。
- 截断连接在列表中用黄色“截断”，不靠 tooltip 才可见；`ws-39` 等长连接也有明确帧数，用户可以先判断值不值得点开。

## 9. 为什么不这么做（反面说明）

- **不用卡片列表。** 17 条规则用卡片会变成 17 个重复标签块，纵向浪费 30% 以上，且 host/path 无法逐行对齐；表格更适合“比较”这个任务。
- **不用折叠树 / 手风琴。** 40+ 连接时折叠项本身就是负担：默认全展开会拉出几屏，默认全收起又看不到帧数。扁平索引 + 筛选 + 右侧详情，点击成本固定为 1 次。
- **不把连接和帧上下堆叠。** 帧表的 5 列在 336px 宽内会被压成省略号；宽而矮的面板应该横向分配空间。
- **不用玻璃拟态 / 模糊 / 半透明。** 面板叠在 DevTools 和网页上，模糊会降低 payload 可读性，也和“调试工具”的可信感相冲突。
- **不用紫色渐变 / 霓虹发光 / 彩色阴影。** 这些会把界面推向营销页；状态只需要低饱和的点和文字。
- **不给每个字段配图标。** “匹配地址 / 重定向目标 / 状态”已经有文字标签，再加图标是重复编码，也会让 42px 行变得嘈杂。整页只有品牌方块和状态点两处图形。
- **不用大圆角卡片和悬浮阴影。** 工具界面的边界应该清楚、稳定；4px 以内的圆角配 1px 线已经足够。
- **不用绿色开关。** 开关表达“启用”，状态表达“是否生效”。两者同色会让“开关开但配置错误”的行自相矛盾。
- **不做假的命中统计 / 命中率。** 代码没有计数器，任何“未命中 0 次”都是编造；状态列只写能验证的事实。
- **不把 Mock 画成可用功能。** DNR 不能返回响应体，界面上直接写“DNR 不支持 / Mock 不生效”，比给一个会失败的开关更诚实。
- **不隐藏无效规则。** 缺目标的规则在列表里标红并禁用保存；如果静默过滤，用户会以为规则生效了。
- **不把总数和筛选数合成一个徽标。** 那样用户在筛选后会误以为只抓到了 22 条连接；所以总数 48、筛选 28、已加载 22 三个数字分别出现，并各自有标签。

### 10.2 截图方式

用 `puppeteer-core` 驱动本机 Chrome，`headless: 'new'`，`deviceScaleFactor: 1`，保留滚动条（`ignoreDefaultArgs: ['--hide-scrollbars']`）。页面加载后隐藏 `.harness`，分别设置 1440×900 与 1200×800 视口，等待渲染完成后整屏截图。三张图均为真实渲染结果，不是手绘或占位图。

已核对：

- 页面 1：17 条规则；9 生效、4 停用、4 异常（3 条 Mock + 1 条缺目标）；2 组冲突；9 条启用且配置完整的转发规则 → 18 条 DNR。
- 页面 2（少）：5 条连接，选中 ws-5，24 帧；方向计数全部 24 / in 14 / out 9 / open 1 / close 0；ws-2 显示 2374 帧 + 截断（缓冲保留 2000）。
- 页面 2（多）：48 条连接；host 筛选 + 只看有帧后 28 条；已加载 22 / 28；选中 ws-31，28 帧；列表 `scrollTop = 176`；无 JS 报错。
- 表格、抽屉、批量条、空态、payload 查看器均在浏览器中实际渲染检查过对齐与文字。

### 10.3 未能验证 / 边界

- 三张 PNG 只覆盖**主列表态**和两种连接规模。编辑校验态、批量选择态、空态、大 payload 查看器在同一 HTML 里可交互复现，但没有作为额外 PNG 交付。
- 页面 1 按桌面宽度（1440）设计；真实扩展 popup 通常只有 360–420px 宽，若直接套用需要另做窄屏布局，本次未验证。
- 状态列的“待授权 / 部分授权”来自代码的权限查询，但截图样本假定域名均已授权，因此画面中没有出现该状态；它复用同一状态样式，不需新增布局。
- 冲突检测、命中计数、暂停滚动、连接/帧筛选都是设计层能力；当前 `sw.js / devtools-panel.js` 未实现对应逻辑，落地时需要补数据与事件。
- 截图使用本机 Chrome 的字体渲染；不同机器的“Microsoft YaHei / PingFang SC”字宽略有差异，1–2px 的换行位置可能不同。
